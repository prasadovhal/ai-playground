# Luna DAG study v1

This is a separate 500-task / 2,000-episode exploratory study, preserving every
previous experiment. All four original framings and API settings remain exact;
one `gpt-6-luna` model, reasoning low, one repetition, primary contrast C-B.

The user authorized a maximum $4 additional exposure after the exact cap request.
`approval.json` records that instruction. This version enforces cumulative Phase 3
$9.363684130, global $9.518315430 and an independent study $4.00 ceiling. The two
historical unverified holds remain counted once; no future unknown request is
automatically encumbered, retried or settled to zero. No credit recharge is used.
These caps protect this experiment, not unrelated account spending.

Task novelty is operationally defined as a distinct directed dependency program:
500 different graph isomorphism classes, including arbitrary node renamings.
Every graph has a join and multiple sources, unlike the old independent chains.
100 structural-profile groups each contain five different topologies. Permuted
operation IDs prevent disclosure of the topological ordering. Programs also mix
resource capacity, register guards, partial write resume and revision conflicts.
Categories have 170 execution, 165 recovery and 165 stopping examples.

These are procedural synthetic constraint programs, NOT 500 independently authored
production workflows. Statistical independence between profile groups is an
assumption; all share an interpreter/grammar and four broader mechanism classes.
The primary profile-family inference is accompanied by a broad-mechanism
sensitivity, and must not support unrestricted generalization. The data set is
not selected to make rivalry look good or bad. Graph, feasibility, restrictions
and failure rules are fixed before model calls and independent of condition.

Gold business states come from a separate exhaustive bitset state-space search,
requiring one terminal state for all legal action orders. A public-observation
oracle verifies the tool engine and injected failures. It never reads the hidden
fault schedule to choose actions. Tool responses contain no gold/fault/family IDs.
Counts/resources/register define final-state correctness; external revision is
protocol metadata. Operational success additionally requires correct final JSON
status, fresh verification and zero constraint violations. Alternative valid
orders are allowed. There is no LLM judge.

The record ID is `batch`, with operation-specific dependencies/permissions and
one revision validation. The original four function names, arguments and schemas
are reused. A partial count-zero operation has applied effects but is not complete;
resuming finishes once without duplicating effects. Count-one operations must
never be repeated. Revision conflicts commit no operation and require revalidation.
Verification lists only unfinished permanently blocked goals, resolving the old
completed-locked-record ambiguity in this NEW version. This changes task semantics;
results must be reported separately from the original studies.

Preregistered N=500 is not an 80–90% small-effect design: prior q=7/54 and paired
ICC about .358 imply about 49% power for a five-point effect under five tasks per
family. The earlier planning results remain in `../luna_planning_v1`. No interim
p-values, sample-size increases, task replacement or stopping based on outcomes.
Primary inference (exact family sign flip and 10,000-draw category-stratified
family bootstrap) is released only at all 500 complete ABCD blocks. Secondary
contrasts/metrics use Holm correction. At a hard budget/infrastructure stop,
produce an audit and descriptive partial report, with no confirmatory p/CI.

Project hash is pinned, exact model access is checked, store=false and retries=0.

persisted episodes are audited and skipped. An orphan reservation or incomplete
episode blocks a new run; no acknowledged API request is automatically replayed.
